# 茶会受付帳

お茶会当日、複数の受付担当がそれぞれのスマホで同じ名簿を見ながら、到着・欠席・備考を記録するための Web アプリです。
ある端末でチェックした内容は、数秒以内に他の端末にも届きます。

---

## 2つの版があります

| | 自前ホスティング版 | Artifact 版 |
|---|---|---|
| 開き方 | **URL を知っていれば誰でも開ける**（LINE でURLを送るだけ） | Claude に同じ組織のアカウントでサインインした人のみ |
| 用意するもの | Firebase プロジェクト（無料）＋置き場所 | なし（すぐ使える） |
| 実体 | `index.html` ほか | `dist/chakai-uketsuke-artifact.html` |

**当日 LINE で配るなら自前ホスティング版**を使ってください。Artifact 版は下ごしらえや動作確認用です。
画面も機能もまったく同じです（`src/app.css` と `src/app.js` を共有しています）。

## いまの状態（このリポジトリ）

`config.js` には Firebase プロジェクト **otyakai-uketsuke** の設定を入力済みで、GitHub にも上げてあります。
**受付で使えるようになるまで、あと3つだけ操作が残っています。**

### ① GitHub Pages を有効にする

リポジトリの **Settings → Pages** を開き、

- Source: **Deploy from a branch**
- Branch: **main** / **/ (root)** → Save

数分後、次のURLで開けるようになります。これを LINE で配ります。

```
https://takayukimatsuzaki917-web.github.io/otyakai-uketsuke/
```

### ② Firebase の匿名ログインを有効にする

Firebase コンソール → **構築 → Authentication → 始める → 匿名 → 有効にする**

受付担当の方にログイン操作は求めません。ページを開いた瞬間に裏側で済みます。

### ③ データベースのルールを貼る

Firebase コンソール → **構築 → Realtime Database → ルール** を開き、
このリポジトリの `database.rules.json` の中身をそのまま貼り付けて **公開**。

> **これが最も大事な手順です。** ルールを貼るまでの間は、
> データベースが「誰でも書き換えられる」か「誰も書き込めない」かのどちらかです。
> `config.js` の値は公開前提のもの（秘密の鍵ではありません）で、
> 名簿を守っているのはこのルールです。**参加者の氏名を入れる前に**貼ってください。

### 動作の確かめかた

1. 上記URLをスマホで開く（真っ白でなく受付画面が出れば①は成功）
2. 歯車 → 組の管理で「A」を追加 → 名簿に2〜3名を貼り付けて登録（登録できれば②③も成功）
3. 別の端末で同じURLを開き、片方でタップして、もう片方に数秒で反映されるか見る
4. 確かめ終わったら 歯車 → リセット → **受付の記録だけ消す** で元に戻す

うまくいかないときは、画面上部に理由が出ます。
「はじめの設定が残っています」なら `config.js`、
「共有できていません（permission-denied）」ならルールか匿名ログインを見直してください。

## 自前ホスティング版のはじめかた（別のプロジェクトで作り直す場合）

### 1. Firebase を用意する（10分ほど）

1. [Firebase コンソール](https://console.firebase.google.com/) で **プロジェクトを作成**（Google アナリティクスは不要）
2. 左メニュー **構築 → Realtime Database → データベースを作成**
   - ロケーションはどこでも可。開始モードは **ロックモード** を選びます（ルールは次の手順で入れます）
   - 画面上部に出る `https://～.firebasedatabase.app` が **databaseURL** です
3. 左メニュー **構築 → Authentication → 始める → 匿名** を選び、**有効にする**
   - 受付担当者にログイン操作は求めません。ページを開いた瞬間に裏側で済みます
4. **プロジェクトの設定（歯車）→ マイアプリ → ウェブ（`</>`）** でアプリを登録し、表示される `firebaseConfig` を控えます

### 2. 設定を書き込む

`config.js` を開き、`firebase` の各項目に控えた値を貼り付けます。`databaseURL` も忘れずに入れてください。

```js
firebase: {
  apiKey:      "AIza...",
  authDomain:  "your-project.firebaseapp.com",
  databaseURL: "https://your-project-default-rtdb.firebasedatabase.app",
  ...
},
roomId: "chakai-20260906"
```

> `config.js` の値はブラウザに配られる前提のもので、**秘密の鍵ではありません**。守りは次のルールで行います。

### 3. データベースのルールを入れる

Firebase コンソール **Realtime Database → ルール** を開き、同梱の `database.rules.json` の中身をそのまま貼り付けて **公開** します。

- 「匿名でよいのでログイン済みの人だけ読み書きできる」ルールです
- 氏名の長さや状態の値も検査するので、壊れたデータが混ざりません
- 手順1で匿名ログインを有効にしていないと、**誰も書き込めません**。必ず有効にしてください

### 4. どこかに置いて URL を配る

このフォルダごと、静的ファイルを置けるところへアップロードします。

- **GitHub Pages**（無料）… リポジトリに push し、Settings → Pages で公開
- **Netlify Drop**（無料・登録なしでも可）… フォルダをドラッグするだけ
- 学校や職場の Web サーバでも構いません

公開されたURLを LINE のトークに貼れば、受付担当の方はそれを開くだけです。
インストールも、ログインも要りません。

> **`file:///` で直接開くと動きません。** 必ず `https://` で配信してください。

## 当日までの流れ

1. URL を開き、右上の **歯車** から設定画面へ
2. **組の管理** で組を追加（A〜G など。「立礼席」のような名前でも可）
3. **名簿の一括登録** で、組を選び、氏名を **改行区切り** で貼り付けて登録
   - 「追記する」… 既にある名前はそのまま、新しい名前だけ足す
   - 「入れ替える」… 貼り付けた名簿に合わせる（消える人数を確認してから実行）
4. 予行で試したあとは、設定画面の **リセット → 受付の記録だけ消す** で元に戻せます

## 当日の使いかた

- 上の **組タブ** で名簿を切り替え。タブに `A 8/13` と到着数が出ます
- 氏名の行を **どこでもタップ** すると到着⇄未到着が切り替わり、到着時刻が自動で記録されます
- 押し間違えたら、下に出る **「取消」** をタップ（5秒間出ています）
- **未着のみ** で、まだ来ていない方だけに絞り込めます
- 名前は言われたが組が分からないときは、**検索欄** に名前の一部を入れると全組から探せます
- 行の右端の **⋯** から、欠席への変更・備考の入力・その方の削除ができます

## リセット

設定画面のいちばん下にあります。**どちらも押すと必ず確認画面が出て**、何がいくつ消えるかを数字で確かめてから実行します。

- **受付の記録だけ消す** … 名簿と組は残し、到着・欠席・備考だけを消して全員「未到着」に戻します
- **すべて消して最初から** … 名簿・組・記録をすべて消します。取り返しがつかないため、確認画面が **2回** 出ます

## 気をつけていただきたいこと

- **URL を知っている人は誰でも名簿を見られます。** 参加者の氏名を扱うので、URL の配布先にご注意ください。
  `roomId` を推測されにくい文字列（例：`chakai-20260906-k7f2q9`）にしておくと、URL そのものが合言葉になります
- 次の茶会で使い回すときは `roomId` を変えるか、URL に `?room=chakai-20270101` を付けると、前回の名簿と混ざりません
- 端末の時計が到着時刻になります。受付前に時刻がずれていないか確かめてください
- 圏外になると上部に「共有できていません」と出ます。復帰すると自動で送られますが、その間の記録は他の端末には届きません

## ファイル構成

```
index.html                 自前ホスティング版の入口
config.js                  Firebase の設定（ここだけ書き換える）
database.rules.json        Realtime Database に貼り付けるルール
src/
  app.css                  画面の見た目（両方の版で共有）
  app.js                   画面のロジック（両方の版で共有。保存先は知らない）
  store-firebase.js        保存先アダプタ：Firebase Realtime Database
  store-claude.js          保存先アダプタ：Claude Artifact の共有ストレージ
build/
  build-artifact.py        src/ から Artifact 版の1ファイルを組み立てる
dist/
  chakai-uketsuke-artifact.html   組み立てた Artifact 版（自動生成。直接編集しない）
```

画面やロジックを直すときは `src/` を編集します。Artifact 版にも反映するには、次を実行してから publish してください。

```
python build/build-artifact.py
```

## 設計のはなし

- **参加者1人＝1レコード**にしています。別々の担当者が同じ組の別の人を同時にチェックしても、互いの記録を打ち消しません
- 一括登録は Realtime Database の「パスごとの一括更新」で **1往復** にまとめているため、91名でも一瞬で、途中で失敗して半端に残ることがありません
- タップした瞬間に画面へ反映し、保存に失敗したときだけ元に戻してエラーを出します。「押したのに記録されていない」状態になりません
